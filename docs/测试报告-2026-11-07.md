## 3. Windows 测试

### 3.1 自动化测试

命令：

```powershell
cd windows
dotnet test NcmConverter.sln -c Release
```

结果：**17 个测试全部通过，0 失败**。覆盖：

- NCM 头解析、长度与偏移校验
- 密钥 XOR/AES 解密、PKCS7 去填充
- 元数据 XOR/Base64/AES 解密、JSON 解析
- artist `[name, id]` 解析
- keybox 构建与流式解密
- FLAC/MP3/M4A 格式嗅探
- 命名清理与重名策略
- FLAC VorbisComment + PICTURE 写入
- MP3 ID3v2.3 + APIC 写入
- 非 NCM 文件、损坏文件的错误码

### 3.2 CLI 验证

```powershell
dotnet run --project src/NcmConverter.Cli -- verify-all ..\testdata
```

4 个样本全部成功，哈希与第 2 节一致。

### 3.3 UI 验证

- 应用启动成功，窗口标题「NCM 转 FLAC」
- 已通过 UI Automation 验证转换、历史、设置、关于四个页面可加载
- 已通过 PrintWindow 截取深色/浅色主题截图，粉色主按钮、进度条、开关与选中态正常
- B站配色：主色 `#FB7299`，辅助色 `#00A1D6`，深色主色 `#FF85A9`

### 3.4 打包

**EXE 安装包（Inno Setup 6）**

- 产物：`dist/Windows/NcmConverter-0.1.0-setup.exe`（60.7 MB）
- 安装方式：逐用户安装到 `%LOCALAPPDATA%\Programs\NcmConverter`，无需管理员权限
- 已执行静默安装测试：自定义目录安装成功，应用可正常打开
- 问题修复：`dotnet publish` 未复制 WinUI 的 `NcmConverter.App.pri`，导致安装版启动时报 `XamlParseException`；构建脚本现已从 Release 构建输出补齐 PRI 与 XBF 资源
- 语言资源：安装目录仅保留 `zh-CN` 与 `en-us`；安装器在升级时自动清理旧版本多余的区域语言文件夹
- 卸载测试：注册表卸载项与开始菜单快捷方式被清理；测试中因应用进程占用，安装目录残留文件已手动清理
- 未使用受信任代码签名证书，SmartScreen 可能提示未知发布者

**MSIX 安装包**

- 产物：`windows/artifacts/msix/NcmConverter_0.1.0.0_x64.msix`（89.1 MB）
- 自签名证书：`windows/artifacts/msix/NcmConverter.cer`
- `signtool verify /pa` 返回证书链不受信任，这是自签名证书的预期结果；安装前需手动信任证书

## 4. Android 测试

### 4.1 核心单元测试

命令：

```bash
cd android
./gradlew testDebugUnitTest
```

结果：**5 个测试全部通过，0 失败**。覆盖与 Windows 相同的解密、元数据、格式嗅探、MP3/FLAC 标签写入，并校验第 2 节黄金哈希。

### 4.2 构建

- Debug APK：16.61 MB
- Release APK：11.45 MB
- Release APK 当前由 Android Debug 证书签名；正式分发前需替换为正式 keystore
- `apksigner verify` 签名校验通过

### 4.3 运行验证

已在 Android SDK Emulator（Android 16 / API 36，x86_64，WHPX 加速，headless）上完成端到端验证：

1. 安装 release APK 并启动，首页布局与 B站粉色主题正常
2. 通过 SAF 文件选择器导入 `sample.ncm`（MP3 源）
3. 应用正确显示歌名「隐藏相册」、歌手「Top Barry / INDEcompany」与 MP3 徽标
4. 点击「开始转换」后成功输出到 `Music/NCM Converter/`：
   `隐藏相册 - Top Barry _ INDEcompany.mp3`
5. 拉取输出文件并使用 TagLib 校验：标题、歌手、专辑正确，内含 1 张封面，时长 156.6 s
6. 历史页显示成功记录（含打开/删除/筛选）
7. 设置页可切换深色主题，界面即时生效

### 4.4 仍未覆盖

- Android 真机（不同厂商 ROM）上的 SAF、前台服务后台运行
- Android 8–9（API 26–28）的存储权限与 MediaStore 分支
- 大文件（> 200 MB FLAC）在 Android 上的转换性能与内存

## 5. 未覆盖项

| 项 | 原因 |
|---|---|
| Android 真机（厂商 ROM） | 模拟器已完成端到端验证；真机仍待测 |
| Android 前台服务在后台/锁屏持续运行 | 模拟器可运行，真机后台策略仍需验证 |
| MediaStore 在 API 26–28 上的写入 | 需要对应版本设备验证 |
| MSIX 受信任安装 | 自签名证书需用户手动导入根证书 |
| 无封面 NCM | 可后续用构造样本覆盖 |
| 旧版 NCM 格式 | 暂无样本，按公开实现尽力兼容 |

## 6. 结论

Windows 与 Android 的核心转换链路已经实现并通过真实样本验证；两端解密结果逐字节一致。Windows 客户端可运行，并产出可直接安装的 EXE 安装包与需信任证书的 MSIX；Android 客户端已在 API 36 模拟器上完成导入、转换、标签/封面、MediaStore、历史与主题的端到端验证，并产出签名 APK。仅剩真机兼容性、Android 8–9 分支与正式签名需要后续补充。

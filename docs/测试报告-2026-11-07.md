## 3. Windows 测试

### 3.1 自动化测试

命令：

```powershell
cd windows
dotnet test NcmConverter.sln -c Release
```

结果：**17 个测试全部通过，0 失败**。覆盖：

- NCM 头解析、长度与偏移校验
- 密钥 XOR/AES 解密、PKCS7 去填充
- 元数据 XOR/Base64/AES 解密、JSON 解析
- artist `[name, id]` 解析
- keybox 构建与流式解密
- FLAC/MP3/M4A 格式嗅探
- 命名清理与重名策略
- FLAC VorbisComment + PICTURE 写入
- MP3 ID3v2.3 + APIC 写入
- 非 NCM 文件、损坏文件的错误码

### 3.2 CLI 验证

```powershell
dotnet run --project src/NcmConverter.Cli -- verify-all ..\testdata
```

4 个样本全部成功，哈希与第 2 节一致。

### 3.3 UI 验证

- 应用启动成功，窗口标题「NCM 转 FLAC」
- 已通过 UI Automation 验证转换、历史、设置、关于四个页面可加载
- 已通过 PrintWindow 截取深色/浅色主题截图，粉色主按钮、进度条、开关与选中态正常
- B站配色：主色 `#FB7299`，辅助色 `#00A1D6`，深色主色 `#FF85A9`

### 3.4 打包

- 产物：`windows/artifacts/msix/NcmConverter_0.1.0.0_x64.msix`（89.1 MB）
- 自签名证书：`windows/artifacts/msix/NcmConverter.cer`
- `signtool verify /pa` 返回证书链不受信任，这是自签名证书的预期结果；安装前需手动信任证书

## 4. Android 测试

### 4.1 核心单元测试

命令：

```bash
cd android
./gradlew testDebugUnitTest
```

结果：**5 个测试全部通过，0 失败**。覆盖与 Windows 相同的解密、元数据、格式嗅探、MP3/FLAC 标签写入，并校验第 2 节黄金哈希。

### 4.2 构建

- Debug APK：16.61 MB
- Release APK：11.45 MB
- Release APK 当前由 Android Debug 证书签名；正式分发前需替换为正式 keystore
- `apksigner verify` 签名校验通过

### 4.3 运行验证

当前测试环境没有连接 Android 真机，已尝试安装 SDK Emulator 与 `system-images;android-36;google_apis;x86_64`。若模拟器可用，将补充启动截图与文件导入/转换测试；若不可用，此项留待用户真机验收。

## 5. 未覆盖项

| 项 | 原因 |
|---|---|
| Android 真机/模拟器 UI 与 SAF 交互 | 当前无连接设备；模拟器安装中 |
| Android 前台服务在后台/锁屏持续运行 | 需要真机验证 |
| MediaStore 在 API 26–28 上的写入 | 需要对应版本设备验证 |
| MSIX 受信任安装 | 自签名证书需用户手动导入根证书 |
| 无封面 NCM | 可后续用构造样本覆盖 |
| 旧版 NCM 格式 | 暂无样本，按公开实现尽力兼容 |

## 6. 结论

Windows 与 Android 的核心转换链路已经实现并通过真实样本验证；两端解密结果逐字节一致。Windows 客户端可运行并产出 MSIX；Android 客户端可编译并产出签名 APK，运行时验收需在真机或模拟器上补充。
